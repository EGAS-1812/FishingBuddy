# FishingBuddy Semantic DB Model

## Overview
This project now uses Entity Framework Core with SQLite via `FishingBuddyDbContext`.

## Tables / Entities
- `Users`
  - PK: `UserID`
  - Fields: `Username`, `Email`
  - Features: angler identity, owns one fishing license, has many catch records, has many favorite fish.

- `FishingLicenses`
  - PK + FK: `UserID` -> `Users.UserID`
  - Fields: `BeginDate`, `ExpirationDate`
  - Features: one-to-one extension table for user license validity period.

- `Fish`
  - PK: `FishID`
  - Fields: `SpeciesName`, `CatchSeason`, `FleshColor`, `FavouriteBaitID`, `PreferredMethodID`
  - Owned value object columns: equipment/reel/rod/line fields (flattened into `Fish` table by EF owned types).
  - Features: core species catalog with recommended bait, technique, and equipment profile.

- `Baits`
  - PK: `BaitID`
  - Fields: `BaitName`, `BaitType`, `PreparationMethod`, `AveragePriceEur`
  - Features: bait catalog reused by fish recommendations.

- `Techniques`
  - PK: `TechniqueID`
  - Fields: `TechniqueName`, `PerformanceNote`, `TutorialUrl`
  - Features: fishing technique catalog with optional tutorial metadata.

- `CatchRecords`
  - PK: `CatchID`
  - FK: `UserID` -> `Users.UserID`
  - FK: `FishID` -> `Fish.FishID`
  - Fields: `CatchDate`, `Weight`, `LengthCm`, `Location`
  - Features: event log of catches made by users for specific fish.

- `FishingSpots`
  - PK: `SpotID`
  - Fields: `SpotName`, `Region`, `HasPiers`, `BoatAccess`
  - Features: geospatial/business metadata about where fish can be caught.

- `UserFavoriteFish` (join table, EF many-to-many)
  - Composite keys generated by EF from:
    - `FavoriteFishFishID` -> `Fish.FishID`
    - `FavoritedByUsersUserID` -> `Users.UserID`
  - Features: maps anglers to their favorite fish list.

- `FishingSpotFish` (join table, EF many-to-many)
  - Composite keys generated by EF from:
    - `MostLikelyCatchFishID` -> `Fish.FishID`
    - `PossibleSpotsSpotID` -> `FishingSpots.SpotID`
  - Features: maps fish species to likely fishing spots.

## Main Connections
- `User` 1:1 `FishingLicense`
- `User` 1:N `CatchRecord`
- `Fish` 1:N `CatchRecord`
- `Bait` 1:N `Fish`
- `Technique` 1:N `Fish`
- `User` N:M `Fish` via `UserFavoriteFish`
- `FishingSpot` N:M `Fish` via `FishingSpotFish`

## Data Access Features
- Repository abstraction remains (`IFishingRepository`) to keep controllers unchanged.
- Runtime implementation switched to EF (`EfFishingRepository`) with includes for navigation loading.
- Startup applies pending migrations and seeds baseline data at app start.
